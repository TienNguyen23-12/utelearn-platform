Mô Hình Phân Quyền Động (Client JSON & Server Permissions)

So sánh quyền giữa danh mục tính năng phía Client và danh sách quyền từ Server, loại bỏ hoàn toàn lối chia cứng /role/feature

Quay lại Quản lý Vai trò
Cách Cũ (Phân Quyền Tĩnh Theo Role & URL)
  • Gắn cứng đường dẫn theo vai trò: /admin/users, /instructor/courses, /moderator/queue.
  • Kiểm tra vai trò trực tiếp: if (role == 'ADMIN') hoặc allowedRoles: ['ADMIN', 'INSTRUCTOR'].
  • Khi tạo vai trò mới hoặc đổi quyền của một vai trò, giao diện và router không thể tự thích ứng nếu không viết thêm code.
  • Người dùng có vai trò khác nhưng được cấp quyền tương đương vẫn bị chặn bởi tiền tố URL vai trò.
Cách Mới (Phân Quyền Động Theo Quyền Hạn Thực Tế)
  • Client: Lưu 1 file JSON danh mục tổng quyền hệ thống (system-menus.json) chỉ định requiredPermissions.
  • Server: Chỉ trả về mảng quyền user đang sở hữu: ["COURSE_CREATE", "ASSET_MANAGE"].
  • Client Engine: Tự động đối chiếu mảng quyền với file JSON, có bao nhiêu quyền thì cấp bấy nhiêu tính năng.
  • Độc lập hoàn toàn với tên Role; thêm bớt quyền trong Database là UI tự động co giãn ngay lập tức.
